## Setup

Identical to SD7003: `length=6, xoffset=-2, yoffset=-1.5`, `dt=0.01`
(`0.005` at the finest grid level), `Re=60800` (UIUC's lowest-Re bin),
boundary resampled to uniform arc-length spacing matched to each run's
`dx` (raw UIUC spacing is again far too non-uniform to use directly —
see SD7003's README for why).

## Files

Same set as `SURF_test/SD7003/`: `polar_comparison.png`, `drag_polar.png`,

`_run_data/` (Python) and `_run_data_cpp/` (C++, new) at the top level.

## Results

**Lift matches well, for both implementations,** across $\alpha=-3.9°$ to
$8.4°$ (e.g. at $\alpha=8.36°$: py $C_l=0.921$, cpp $C_l=0.889$, both vs.
exp $C_l=1.034$ — see `new/summary.txt`) — see `new/polar_comparison.png`.
Same qualitative story as SD7003, now corroborated by an independent
implementation.

**Drag is overpredicted at higher $\alpha$, by both implementations,** for
the same reasons as SD7003 (no transition model, under-resolved laminar
separation bubble physics at Re≈60800): at $\alpha=8.36°$, py
$C_d=0.147$, cpp $C_d=0.133$, both vs. exp $C_d=0.028$.

**Grid convergence (`new/grid_convergence.png`)**, at mild $\alpha=-0.81°$:
this case shows an even more dramatic convergence story than SD7003's, in
**both** implementations. `py/ibpm.py`'s coarsest grid (dx=0.04) gets the
*sign* of $C_l$ wrong (py $-0.149\pm1.22$ vs. exp $+0.065$); C++'s coarsest
grid is even more extreme — $+0.85\pm46.5$, i.e. the instantaneous force
trace swings wildly enough that the std. dev. is **~55x** the mean, direct
numerical evidence that dx=0.04 does not resolve this flow *at all* for
either implementation (this is exactly the kind of number a plotted error
bar would render meaningless/off-scale, and part of why `new/`'s figures
don't draw them — see `../SD7003/README.md`'s "About the error bars").
Both implementations' medium (dx=0.02) and fine (dx=0.01) grids recover the
correct sign and converge toward the experimental value, with the
unsteadiness collapsing sharply (py $C_l$ std: 1.22 → 0.31 → 0.04; cpp
$C_l$ std: 46.5 → 0.33 → 0.05, coarse to fine). This is the clearest
evidence in either airfoil case — now doubled by cross-implementation
agreement — that the coarse-grid disagreement is a genuine resolution
artifact rather than a modeling error. Full numbers in `new/summary.txt`.

**Same finest-grid CFL divergence** as SD7003 was hit here too, **in both
implementations** (dx=0.01 diverged to `NaN` at `dt=0.01`, fixed the same
way with `dt=0.005`) — see `SURF_test/rerun_fine_log.txt` (Python) and
`run_all_airfoils_cpp.py` (C++).

## Limitations

Identical caveat to SD7003: `new/flow_evolution.png` shows the same
broadband grid-scale noise spreading through the domain at this
Re/resolution, **in both `py/ibpm.py` and C++ `build/ibpm`** — trust the
integrated force/convergence numbers over the flow-field snapshots.
