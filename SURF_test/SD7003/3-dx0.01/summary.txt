SD7003 flowfield case, dx=0.01 (fine grid) vs. dx=0.02 baseline
alpha=4.60 deg, Re=61100, ngrid=1, nx=600, ny=300, dt=0.005 (halved from
this suite's usual dt=0.01 -- SD7003/README.md documents that the dx=0.01
level diverges to NaN at dt=0.01 in both implementations; the same halved-dt
fix used for the polar/grid-convergence sweeps was applied here), nsteps=6000
(t=30, same physical-time window and snapshot cadence -- t=0,5,...,30 -- as
2-c++included/'s dx=0.02 baseline).

Context: same mentor question as 3-ngrid=3/ (see that folder's summary.txt
for the initial-condition check against the UIUC LSAT dataset -- unchanged
here, Re=61100 already matches LSAT's own stated value, impulsive-start IC
is standard and matches the C++ reference).

Result: dx=0.01 ran stably for the full t=0..30 window in both
implementations (no NaN; max |Cl| ~1.7, max |Cd| ~0.14 throughout -- see
flow.force in _run_data_dx001{,_cpp}/flowfield/). py/ibpm.py and C++
build/ibpm agree closely at every snapshot (flow_evolution.png).

However, halving dx does NOT clean up the broadband vorticity speckle
either -- if anything the finer grid resolves *more* small-scale structure
in the noise, not less, consistent with SD7003/README.md's explanation that
the speckle is a real feature of this Re/resolution regime (no subgrid
dissipation to damp grid-scale noise) rather than a coarse-grid artifact
that finer dx would remove.
