================================================================================
  BINARY FILE FORMAT (QUICK REFERENCE)
================================================================================

Each .bin file contains (in order):

  [Header - 22 bytes]
    nx (int, 4 bytes)
    ny (int, 4 bytes)
    ngrid (int, 4 bytes)
    dx (double, 8 bytes)
    x0 (double, 8 bytes)
    y0 (double, 8 bytes)

  [Geometry - 4 bytes]
    numPoints (int, 4 bytes)

  [Flux - ngrid * numFluxes * 8 bytes]
    Flux data (double array)
    numFluxes = (nx+1)*ny + nx*(ny+1)

  [Omega - ngrid * (nx-1) * (ny-1) * 8 bytes]
    Vorticity (interior points only)

  [Forces - numPoints * 2 * 8 bytes]
    Boundary forces (fx, fy pairs)

  [Time - 12 bytes]
    timestep (int, 4 bytes)
    time (double, 8 bytes)

See VALIDATION_SETUP.md for complete format details.

================================================================================
  KEY INSIGHTS FOR PORTING
================================================================================

1. INDEX CONVENTION:
   - C++ uses 1-indexed interior loops: for(i=1; i<nx; ++i)
   - Python should use 0-indexed or be explicit about padding
   - Flux/omega storage use row-major indexing

2. ARRAY LAYOUT:
   - Flux: X-fluxes (linear 0-N) then Y-fluxes (linear N-M)
   - Omega: interior only, no boundary (implicitly zero)
   - Forces: flat [fx1, fy1, fx2, fy2, ...] pairs

3. FLOATING-POINT:
   - Use rtol=1e-10 for double-precision comparison
   - Check for NaN carefully; they propagate silently
   - FFTW vs SciPy FFT have different normalization

4. PERFORMANCE:
   - Initial port: correctness > speed
   - Use NumPy for all grid operations (avoid Python loops)
   - Replace custom Cholesky with scipy.linalg.cholesky
   - Replace FFTW sine transform with scipy.fft.dst

5. TESTING:
   - Start with data I/O (load/save), not computation
   - Each stage should have comprehensive validation
   - Use reference files as ground truth, not derivative calculations
